# atomvm-cbor 0.3.0 validation report

This report records the public, matched benchmark evidence for the 0.3.0
release candidate against public release 0.2.0.

## Provenance and methodology

- Baseline: public tag `0.2.0`.
- Candidate: public 0.3.0 release branch.
- Host measurements use the same source harness, payloads, compiler flags,
  scheduler topology, warmup count, sample count, and alternating run order for
  both versions.
- Each reported host value is the median of five complete paired runs. Each
  run-level value uses 31 samples after 1,000 warmups.
- Lower latency is better. The fail-closed regression limit remains 5% for
  median and p95 on directly comparable workloads.

Exact host results will be inserted from the committed public candidate before
the release branch is pushed.

## New API workloads

The 0.3.0 harness covers `encode_with_size/1`, `encode_sequence/1`,
`sequence_fold/3`, `validate_all/1`, `partial_map_fold/3`,
`partial_array_fold/3`, `partial_select/2`, `partial_map_find/2`, and
`partial_array_nth/2`. These APIs do not exist in 0.2.0, so their baseline is
reported as `N/A` and no percentage improvement is invented.

## Hardware measurement status

No 0.3.0 attached-device performance values are reported in this document.
The partial descriptor validation path changed, so the 0.2.0 partial-accessor
measurements are retained only in the 0.2.0 historical report and are not
relabelled as 0.3.0 evidence. Public ESP-IDF checks validate build integration,
not physical-device timing.

## Reproduction

From the public repository at the committed 0.3.0 candidate:

```bash
BENCHMARK_RUNS=5 BENCHMARK_NOISE_TOLERANCE_PERCENT=5 \
  bash scripts/benchmark-remediation.sh
```

The command selects the greatest reachable SemVer tag below `VERSION`, records
the selected public baseline, runs both versions under identical conditions,
and fails if a comparable median or p95 exceeds the unchanged tolerance.
