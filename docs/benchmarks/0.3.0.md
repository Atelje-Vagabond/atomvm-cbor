# atomvm-cbor 0.3.0 validation report

This report records the retained matched evidence used for the public 0.3.0
release comparison against public release 0.2.0. No benchmark was rerun to
prepare this report.

## Provenance and methodology

- Baseline: public tag `0.2.0`, commit
  `50cae38fc0d846e41fe61c9d5d80229c6cff91f2`.
- Remediated 0.3.0 runtime evidence: release-validation commit
  `12903636339edb1172167d3905907ff583ffd7d2`, retained run `32586422115`.
  The ESP discovery log in job `97064781219` binds the capture to WaveShare
  UART serial `5B61092782`; the workflow and R2 platform key use the generic
  `esp32-s3` name.
- Public candidate incorporates the same focused OTP 29 remediation in the
  benchmark-relevant decoder and partial-decoder paths while retaining the
  public continuation API.
- Host: Dell, Intel Pentium Silver J5005, Linux x86_64, OTP 29 / ERTS 17.0.5,
  one scheduler, digest-pinned Erlang container.
- Host sampling: five alternating fresh-VM pairs; 31 samples per workload
  after 1,000 warmups. Reported values are medians of the five run-level
  medians and p95 values.
- Attached runtime: AtomVM 0.6.6. The attached benchmark harness is unchanged
  from 0.2.0 (`eb0d179817bc058a2b3aedf9c245c07b072387500a609c167a93e6dfb0f8c127`).
  Common/partial workloads use 50 iterations after warmup and accessors use
  250 iterations after warmup; values are microseconds per call.
- Lower latency is better. The host fail-closed regression limit remains 5%
  for median and p95 on directly comparable workloads.

## New API workloads

The 0.3.0 host harness also covers `encode_with_size/1`, `encode_sequence/1`,
`sequence_fold/3`, `validate_all/1`, `partial_map_fold/3`,
`partial_array_fold/3`, `partial_select/2`, `partial_map_find/2`, and
`partial_array_nth/2`. These APIs do not exist in 0.2.0, so their baseline is
`N/A` and no percentage improvement is invented.

## Reproduction policy

The canonical host command remains:

```bash
BENCHMARK_RUNS=5 BENCHMARK_NOISE_TOLERANCE_PERCENT=5 \
  bash scripts/benchmark-remediation.sh
```

This report was assembled from the retained outputs above; the command was not
rerun merely to regenerate documentation.
